# samba-shares-ad
# Изолированные домашние каталоги пользователей AD на базе Debian 13 + Samba 4.22

Реализация файлового сервера на Linux (Debian 13.7) с интеграцией в многодоменный лес Active Directory. Проект решает задачу безопасного хранения личных файлов пользователей с теневым восстановлением удаленных данных.

## Техническое задание и требования
1. **Единая точка управления в AD:** доступ к личному каталогу открывается только после того, как администратор укажет путь к серверу в атрибуте `homeDirectory` учетной записи пользователя в Active Directory.
2. **Строгая изоляция (ABE):** пользователи не видят чужие папки в корне шары, а администраторы домена имеют полный доступ ко всем каталогам.
3. **Защита корневой папки пользователя:** внутри своего каталога пользователь имеет полные права (чтение, запись, удаление файлов), но не может удалить или переименовать саму свою корневую папку.
4. **Теневая корзина (Shadow Recycle):** любые удаляемые пользователем файлы перемещаются в скрытую корзину с сохранением версий и структуры каталогов. Пользователь корзину не видит и доступа к ней не имеет.
5. **Автоматическая ротация:** файлы в корзине хранятся 30 дней, после чего автоматически удаляются по расписанию.

## Архитектурные решения

### 1. Почему чистый Winbind, а не SSSD
Для интеграции с AD выбрана нативная связка `Winbind` + `Kerberos` (`security = ads`) вместо SSSD.
* **Теория и позиция разработчиков:** начиная с Samba 4.8.0, служба `smbd` для работы с сетевыми шарами в домене требует обязательного наличия запущенного `winbindd` (SSSD не поддерживает NTLM и использует собственную библиотеку `libwbclient`). По рекомендациям мейнтейнеров Samba (Rowland Penny), совмещать SSSD и Winbind на файловом сервере не рекомендуется из-за конфликтов маппинга:
  * [Архив рассылки Samba: обсуждение SSSD и Winbind (июль 2024, часть 1)](https://lists.samba.org/archive/samba/2024-July/249443.html)
  * [Архив рассылки Samba: обсуждение SSSD и Winbind (июль 2024, часть 2)](https://lists.samba.org/archive/samba/2024-July/249448.html)
* **Практический опыт тестирования:** связка `SSSD + Winbind` показала себя нестабильно: наблюдалось медленное и некорректное получение списков групп и SID пользователей от контроллеров домена. Кроме того, конфигурация работала ровно до первого рестарта `winbind` — сервис не мог корректно стартовать при уже запущенном `sssd.service`. Переход на чистый Winbind полностью решил проблему.
* **Чтение атрибутов AD:** получение атрибута `homeDirectory` из AD (включая корректный парсинг LDIF и декодирование Base64 при наличии кириллицы) реализовано через `net ads search -P` от имени машинной учетной записи сервера без расширения схемы и создания лишних сервисных аккаунтов.

### 2. Модель прав (Owner + POSIX ACL)
* Владельцем всех домашних папок назначен `root` (`0:0`, права `0750`), что физически запрещает пользователю удалить или переименовать свой корневой каталог.
* Гранулярные права выдаются через POSIX ACL (`setfacl`): пользователь получает `rwx` на содержимое с наследованием (`default ACL`).
* Включены `access based share enum = yes` и `hide unreadable = yes` в Samba для скрытия чужих директорий.
* При подключении пользователя (`root preexec`) скрипт автоматически проверяет корректность владельца, ACL и масок, защищает от path traversal и симлинков, а при обнаружении конфликта чужого UID безопасно архивирует старую директорию.

### 3. Теневая корзина (`vfs_recycle`) и автоматизация
* Корзина реализована через VFS-модуль `recycle` внутри каталога пользователя (`.recycle`), полностью скрыта и заблокирована от доступа по сети параметрами `veto files = /.recycle/` и `delete veto files = no`. Включено версионирование (`recycle:versions = yes`), чтобы одноименные удаленные файлы не перезаписывали друг друга.
* Включены `recycle:touch = yes` и `recycle:touch_mtime = yes`, однако в актуальных версиях Samba сохраняется поведение, при котором `mtime` при перемещении обновляется не всегда — поэтому скрипт очистки надежно опирается на `ctime` (время изменения статуса инода при перемещении файла в корзину).
* Скрипты обслуживания на Bash написаны с защитой от параллельного запуска (`flock`), строгой валидацией входных параметров и централизованным логированием в `systemd-journald` (через `logger`).
* Очистка корзин старше 30 дней настроена на ночной запуск по расписанию (cron / systemd-timer) от имени `root`.

## Стек и версии ПО
* **ОС:** Debian GNU/Linux 13.7 (`trixie`)
* **Ядро Linux:** `6.12.63+deb13-amd64`
* **Samba / Winbind:** `4.22.11+dfsg-0+deb13u1`
* **Kerberos (`krb5-user`):** `1.21.3-5+deb13u1`
* **Утилиты ФС (`acl` / `attr`):** `2.3.2` / `2.5.2`
* **Оболочка:** GNU Bash `5.2.37`

## Структура репозитория
* `configs/smb.conf` — конфигурационный файл Samba с настройками домена, прав, `root preexec` и модуля `vfs_recycle`.
* `configs/krb5.conf` — базовая конфигурация клиента Kerberos (`[libdefaults]`).
* `configs/nsswitch.conf` — конфигурация NSS с подключением бэкенда `winbind`.
* `scripts/mk-share-folder.sh` — скрипт создания домашнего каталога, проверки `homeDirectory` в AD и применения POSIX ACL.
* `scripts/clean-samba-recycle.sh` — скрипт ночной очистки файлов в корзине старше 30 дней по `ctime` и удаления пустых подпапок.
